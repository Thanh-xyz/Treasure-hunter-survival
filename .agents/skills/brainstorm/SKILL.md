# Brainstorm

Use the installed general brainstorming methodology, then apply these project
constraints.

## Input

- Completed scout findings.
- Verified code and visual evidence.
- Ownership boundaries and unresolved decisions.

## Output

- Two or three materially different approaches.
- Tradeoffs for fidelity, compatibility, conflicts, performance, maintenance,
  evidence quality, and local-only asset use.
- One recommendation and the conditions under which alternatives would win.

## Acceptance Criteria

- Visual recommendations prioritize direct Treasure Hunter evidence.
- Recommendations preserve the Godot project and stable gameplay contracts.
- Assumptions and unknowns are explicit.
- Planning can proceed without treating a proposal as implemented fact.

## Failure Handling

Do not invent alternatives when only one approach is viable. Return unresolved
stakeholder decisions to the workflow gate.
